# The Shape tool and point editing

## TL;DR

**The Shape tool** draws the four kinds a ShapeComponent holds. Its options strip offers Rectangle, Circle and Polygon; a line is a polygon drawing finished open. While it is active the Inspector is hidden. Finishing runs **`createShape`**, one step, and the tool returns to Select with the new shape selected. **Point editing** is a state of the Select tool, entered by double-clicking a polygon or line: its points are selected, dragged, nudged, added on an edge and deleted, each one step. Stage 10 builds both; its choices are at the end. The tool contract, `ToolController` and snapping are in [selection-and-tools.md](selection-and-tools.md).

## The Shape tool

- One tool, four kinds: rectangle, circle, polygon and line. **Its options strip offers Rectangle, Circle and Polygon** (owner, 2026-11-15); a line is a polygon drawing finished open. The tool remembers the kind used last, a rectangle at first.
- **Choosing it clears the selection and hides the Inspector** (owner, 2026-11-15). `InspectorModel` only ever describes entities in the level, never a shape being drawn, so it needs no case for something that isn't an entity. The Inspector shows again when the tool is left: after a shape is finished the tool returns to Select with the shape selected.
- A faded preview follows the mouse; a click places it at the remembered size, a drag sets a new size. A circle's drag gives the circle that fits the box, as if Shift were held. Resizing a circle with the Select tool's handles keeps it round: the radius follows the larger stretch.
- Polygon: each click adds a point; clicking the first point closes it into a polygon; Enter, Esc, double-click, choosing another tool or Play finish it open, as a line (fewer than 2 points is dropped); Ctrl+Z or Backspace removes the last point.
- **Z and X turn the preview** (stage 18): the tool keeps one turn, in degrees in the current group's own space, which `createShape` writes as the new TransformComponent's Rotation. See the stage 18 entry below.
- Finishing runs `createShape`: a TransformComponent, a ShapeComponent and a StyleComponent with the v1 default look, in the current group, on top, named by `EntityNamer` ("Rectangle 1": one more than the highest number already used with that word), and selected.

## Point editing

- **`PointEditState`** of the Select tool, entered by double-clicking a polygon or line, as the double-click table says. The entity stays selected, so the Inspector shows its Points while its points are edited.
- It holds the **selected points** as indexes into the entity's points. A click selects one, Shift+click adds or removes one, a drag on empty space inside the level view selects the points its box touches.
- Dragging points, nudging them, adding a point on an edge and deleting points each make one step, through `LiveEdit` for drags and the edits in `editor/commands/points` for the rest.
- Esc goes back to the Select tool's `IdleState` with the entity still selected.

## Stage 10's choices

Made under the standing yes (2026-11-16), before building. The [plan](../../steps/stage-10.md) has the steps.

- **`createShape` is an edit, not a registered command**, in a new `editor/commands/draw`, beside `moveEntities`: it has no menu place and no key, and only the Shape tool runs it. It takes the kind, the geometry in the current group's space and the position, and returns the new id for `finished`. The step is `Draw Rectangle 1`. *Why: the [command registry](clipboard-and-shortcuts.md) holds what the menu and the keys run; the plan's `CreateShapeCommand` named the job, not a registered command.* **As built** (standing yes, 2026-11-16): `createShape(openLevel, reader, drawing)` takes the session's `LevelReader` too, since the new entity is added through `AddEntitiesChange` like Group's, and returns `created` with the id or `refused`; the shape gets a NameComponent for its name beside the other three; it is also refused, with Group's `Groups can be at most 256 deep`, when the current group is already that deep. *Why: a tool's context holds the open level but not the session, so stage 10 step 3 adds the reader to `ToolContext`.*
- **`EntityNamer`'s words** are the kind's name: `Rectangle`, `Circle`, `Polygon`, `Line`. A polygon finished open is named `Line`.
- **A shape is drawn in the current group's own space**: the mouse's level positions go through the group's inverted level matrix, so under a rotated group the box is drawn along the group's sides and the new shape needs no rotation of its own. **Its position is the centre of its box**, a rectangle and a circle centred on it as `ShapeGeometry` keeps them, a polygon's or line's points around it. *Why: rotating and resizing then turn around the middle of what was drawn, as the Select tool does.*
- **A click places the preview centred on the mouse** at the remembered size, 100 × 100 px at first and a circle 50 px in radius (*proposal*). *Why: the preview is then centred under the mouse, so it shows exactly where the click puts it.* The remembered kind and size live in memory for the session, like the card folds before stage 12.
- **A drag** goes from the press to the mouse: Shift keeps a square, Alt draws from the press as the centre, both together a square from the centre. The moving corner snaps as a point (`snapPoint`), Ctrl turns that off. A press that moves less than 4 screen px is a click. The readout shows the size, `200 × 100 px`, or the circle's `⌀ 100 px`, as the Select tool's resize readout does. On release each side is at least 1 px.
- **As built in step 3** (standing yes, 2026-11-16): `ShapeTool` in `editor/tools/shape/`, the box maths in `boxDrawing.ts`. **The press snaps as a point too**, not only the moving corner, and so does the hover preview's centre. *Why: with only the corner snapped a drawn box never lands on the grid, and the preview would not show where a click puts it.* **Each kind remembers its own size** (a rectangle's sides, a circle's width across), so a rectangle drag doesn't change the next circle. **Choosing another tool during a drag makes nothing**, as Esc does, since nothing is placed until the release. Shift, Alt and Ctrl pressed during a drag redraw it at once. The tool publishes `drawing` (the `ShapeDrawing` in the current group's space and the matrix to level positions) and `readout` for step 8's overlay, and an `options` counter that moves when the kind changes, for step 9's strip. The readout's texts moved from `tools/select/readout/` to `tools/readout/`, shared by both tools; `ToolContext` gained `reader`.
- **A polygon's points** snap as points; Shift turns the segment from the last point to a multiple of 15°. The first point closes it when a click lands within 8 screen px of its middle (*proposal*: the 12 px ring with a little room), and only with 3 points or more; with fewer, that click is ignored. The second click of a double-click adds no point; it finishes the drawing open. **The 1,001st point is refused** with the status text `A polygon holds at most 1,000 points`, and the drawing goes on.
- **Ctrl+Z and Backspace while drawing** reach the tool first, since `ShortcutDispatcher` gives a tool its own keys before the commands. Removing the only point ends the drawing with nothing made. Ctrl+Z with no drawing undoes as usual.
- **Esc's drawing step** finishes and keeps the polygon (the requirement: no key throws work away), so the next Esc returns to Select. Esc during a rectangle or circle drag ends the drag with nothing made, since the drag is the drawing's only step and nothing is placed until the release.
- **Play finishing the drawing** is `ToolController`'s `deactivate` of the active tool, which stage 16's Play calls; stage 10 builds and tests the call, not Play.
- **Drawing inside a locked group is refused** with `This group is locked`, though locking is v3, as stage 9 honoured the lock: one check in `createShape` and one at the tool's press.
- **As built in step 4** (standing yes, 2026-11-16): **Ctrl+Z reaches the tool through a new `undoDrawingStep()`** on the tool contract, which `ShortcutDispatcher` asks through `ToolController` when a press matches Undo's shortcut, before running Undo. *Why: Undo's chord already knows every layout (a German Ctrl+Z is on the Y key), and `editor/tools` can't read the shortcuts.* During a rectangle or circle drag it does nothing, as Ctrl+Z does during the Select tool's drags. A point is added on the release of a click, so Esc while the button is still down drops only that point (Esc's drag step). **Esc keeps the shape without returning to Select**: the tool stays on Shape with the new shape selected, so the next Esc returns to Select as written above; another tool and `deactivate` keep it too and go to the tool picked; Enter, a double-click and closing return to Select. **With Shift a point isn't snapped to the grid**: it keeps its distance from the last point, turned to the nearest 15° in the current group's own space. **A click on the last point's place adds nothing**, since it would make a segment of no length. **Changing the kind during a drawing keeps drawing the polygon**, as a drag keeps its kind. The polygon's position is the middle of its points' box. The tool publishes `polygonDrawing` (the points, the next point or the first point when a click would close it, and the matrix to level positions) for step 8's overlay, the next point alone before the first click. The test helpers moved to `tools/shape/testing/`.
- **The tool hints** (*proposal*): rectangle and circle `Click to place, drag to size. Shift keeps proportions, Alt draws from the centre.`; polygon `Click to add points. Click the first point to close it, Enter to finish as a line.`; point editing `Drag points to move them. Double-click an edge to add one. Esc goes back.`
- **The preview overlay**, `DrawingPreviewOverlay` in `adapters/pixi/overlays/drawing/`, draws the Shape tool's published preview as [the level view's colours](../../design/level-view.md) say: the default fill at 35%, the placed segments solid and the segments to the mouse and back to the first point dashed at 60%, the placed points as 8 px handles and the first one as a 12 px ring. `PixiLevelView` takes it beside the selection; `planDrawing` is tested in Node, as `planSelection` is. *Why the name: the architecture's `ToolPreviewOverlay` only ever draws a drawing in progress, so it is named for that.*
- **The page:** the toolbar gains the Shape button (key 4), the `ToolOptions` strip shows the three kinds while the Shape tool is active, and `EditorShell` hides the Inspector's panel place while it is, the free area's corner moving right of the toolbar as [controls.md](../../design/controls.md) says.
- **The high detail note** is an editor message: `HighDetailRule` gives a polygon or line over 200 points the tip `High detail may slow physics`, checked like the other rules once per frame for changed entities.
- **As built in step 5** (standing yes, 2026-11-16): `HighDetailRule` in `editor/messages/rules/`, in `createV1Rules` after the other two. **The tip sits under the Points field** (`fieldKey: 'points'`), not on the whole card. *Why: the count of points is what it is about, and the Points field is shown exactly when the shape is a polygon or line.* A rectangle or circle never gets it, however large.
- **Point editing, as planned here:**
  - A point is hit within 6 screen px of its middle (the 8 px handle with a little room), an edge within 5 screen px, as a line's hit area. Selected points draw filled with the accent colour, the others hollow. The handles stay 8 px at any zoom.
  - **The Select tool takes its keys first while editing points**: the arrows nudge the selected points through the same 1, 10 and grid steps, joined by `nudgePoints:` plus the entity's id; Delete and Backspace delete them. *Why: the dispatcher gives a tool its keys before the commands, so the entity nudges and Delete never see these presses.*
  - **Deleting** stops at a polygon's 3 or a line's 2 points with the status text `A polygon keeps at least 3 points` or `A line keeps at least 2 points`, and deletes nothing then.
  - **Double-clicking an edge** adds a point where it is clicked, on the edge, and selects it; dragged points snap as points.
  - **Point editing ends** with Esc, a click on another entity (which selects it), a click on empty space outside the shape's frame, a change of selection from elsewhere, or the entity going away. Undo and Redo clear the selected points, since their indexes may no longer match.
  - **A path's points wait for v2's pen** (standing yes, 2026-11-16): nothing in v1 makes a path with points (the Bézier pen and the Pencil are v2, and a Rope's or Spring's path is read-only), so curve handles and sharp or smooth points have nothing to edit. A double-click on a path only selects, as on a rectangle. *Why: the requirement lists paths under v1 point editing, but building handles nobody can reach is untested work; the owner can say otherwise.*
- **As built in step 6** (standing yes, 2026-11-16): `PointEditState`, `PointPressState` (a press, until it is a click or a drag) and `PointBoxState` (the box of points) in `tools/select/states/`, beside the other states, since a folder of their own would make a circle of folders with `doubleClick`; `EditedPoints` (the entity and its selected indexes) and `PointHits` (a point within 6 screen px, an edge within 5, the points in a box) in `tools/select/points/`. `SelectTool.editedPoints` publishes the entity and its selected points for step 8's overlay, during a press and a box too, and the frame's handles hide while points are edited. **A press on another entity ends point editing and is handed to `IdleState`**, so it selects as a press there always does and a drag moves it. **A click on empty space outside the frame ends it and clears the selection**, as the Select tool's click there does; Esc keeps the shape selected. A click on the shape, or on empty space inside its frame, clears the selected points; **a click within 5 screen px of an edge counts as on the frame**, so a line's thin box can be clicked beside. A press on an unselected point selects it at once, so step 7's drag moves it; a selected one narrows on release, as entities do. **Point editing also ends when the shape is hidden, locked or changes kind**, since its points are then not there to edit, and a deleted point's index is dropped from the selected points. Esc during a box drops the box and stays in point editing. Leaving the Select tool ends point editing. Undo and Redo are seen through a new `History.undoneOrRedone` counter, since `History.version` also moves on a new step, which must not clear the points that step 7's drag just moved. *Why: each is what the Select tool already does outside point editing, so nothing behaves differently by surprise.*
- **As built in step 7** (standing yes, 2026-11-16): the edits are in `editor/commands/points/`: `PointsTarget` reads a polygon's or line's points with its level matrix turned around, so a level position becomes a point in its own space whatever its parents' rotation, scale and skew; `PointsMove` moves given points by a level offset, shared by the drag and `nudgePoints`; `addPoint` and `deletePoints` each make one step. **All four write the geometry through `LiveEdit`**, as `nudgeSelection` does, so no new change type was needed. The steps read `Move points of Polygon 1`, `Add a point to Polygon 1` and `Delete points of Polygon 1`. They are refused during a drag, on a locked shape (`Locked entities don't move`) and on a shape without points. `PointDragState` in `tools/select/states/` is the drag: **only the pressed point snaps as a point** and the others keep their distance from it, Ctrl turns that off, Esc puts the points back, and the readout shows the offset as a move's does. A Shift+press on an unselected point adds it when the drag starts, so it moves too. **While editing points the arrows and Delete or Backspace are the tool's even with no point selected**, so they never move or delete the whole shape by surprise; like the Shape tool's Enter and Backspace they work wherever the keyboard is except a text field, not only with the mouse over the level view, since the tool's keys don't know where the mouse is. Deleting clears the selected points, since the indexes after them move down. **The 1,001st point is refused** with `A polygon holds at most 1,000 points` (or `A line`), as drawing refuses it. A double-click on a point does nothing until v2's sharp and smooth points. The point editing test level moved to `tools/select/testing/pointTest.ts`.
- **As built in step 8** (standing yes, 2026-11-16): `DrawingPreviewOverlay` and `planDrawing` in `adapters/pixi/overlays/drawing/` read a new **`DrawingSource`**, the Shape tool's `drawing` and `polygonDrawing` while it is the active tool, built by `EditorDrawingSource` in `app` and handed over with `PixiLevelView.showDrawing`. The overlay sits under the selection overlay, so the readout stays on top, and **the Shape tool's size readout shows through the selection overlay's readout**, which now reads it from either tool. A rectangle or circle preview is filled and **outlined solid in the default outline colour, 1.5 screen px** (*proposal*), since it has no segment still to place. **Before the first click the next point shows as a handle**, so a snapped first point shows where it lands. **The first point's ring fills with the accent colour when a click would close the polygon**, the 12 px measured to its outside. The point handles reach `SelectionOverlay` as `editedPoints` (the points in level positions and the selected indexes) from `SelectTool.editedPoints`, the selected ones filled with the accent colour and the others white with the accent edge, as the frame's handles are. The dashes and the handle's square moved to `overlays/dashes.ts` and `screenPixels.ts`, shared by both overlays; the default colours are exported from `core/components`. The Shape tool joins the tools in step 9, so until then nothing on the page uses the preview. *Why: each piece follows how the selection overlay already reads the Select tool.*
- **As built in step 9** (standing yes, 2026-11-16): `createTools` holds the Select and Shape tools, so key 4 and the Shape button pick it. `ToolOptions` in `ui/tool-options/` sits in the free area, 8 px from its top left, and shows `ShapeOptions` while the Shape tool is active: each choice an `OptionButton`, the Entities panel's icon for the kind and its name, the chosen one on. **`EditorShell` drops the Inspector's place and its grid column** while the Shape tool is active, so the free area, and with it the strip and the view's fitting, reaches the toolbar; the Inspector comes back when the tool is left, showing the new shape. **The Select tool's hint is point editing's while points are edited.** *Why the hint follows `preview`:* a hint that changes with the tool's state needs a signal, and every such change already redraws the overlay, so the tool contract says a hint changes only when `preview` moves (the Select tool now moves it on every change of state, and the Shape tool when the kind changes), and `ToolController.hintVersion` follows its own version and every tool's preview, which the status bar reads.
- **The Playwright tests** draw each kind by click, drag, Shift and Alt, close a polygon and finish one as a line, remove a point with Ctrl+Z while drawing, group two drawn shapes and go into the group and out with double-click and Esc (the test stage 9 left), and edit a polygon's points with a drag and an undo.
- **As built in step 10** (standing yes, 2026-11-16): the tests are `tests/e2e/shape-tool.spec.ts`, eight of them. **Each turns grid snapping off first**, so two drags of the same length give the same size wherever they start, and the sizes are checked against each other (Shift's square, Alt's twice the size, a circle's drag as if Shift were held) instead of against numbers worked out from the zoom. **Playwright now runs in Chromium, Firefox and WebKit**, as this step asked, and so does CI's journeys job; all 114 tests passed in the three on the first run.
- **Z and X as built** (standing yes, 2026-11-17, stage 18 step 11): **`ShapeTool.keyDown` takes Z and X itself**, before the commands, as it takes Enter and Backspace; `previewTurnOf` reads the letter as the shortcuts do (the typed letter, or the physical key when the layout types no Latin one) and leaves Ctrl and Alt alone, so Ctrl+Z and Ctrl+X stay Undo and Cut. `ShapeDrawing` gains **`rotation`**, and `planDrawing` draws the preview through `Matrix2D.fromTransform`, so it shows exactly the shape made. **A box drag is measured along the turned sides**: `draggedBox` turns the mouse back around the press, so Shift, Alt and Ctrl+Shift keep their meaning. **A polygon's or line's placed points turn around the middle of the shape they would make** (`turnedPoints`), and `pointsDrawing` turns them back by the rotation, so the made shape's own points and box follow the turn while its points stay where they were placed. In a mirrored current group the turn is stored the other way, so X still turns clockwise on screen, as the Z and X commands do. **The turn is reset when the tool is picked** and kept while it stays active, so a locked tool keeps it from shape to shape; turning makes no undo step. Both hints end `Z and X turn it.` *Why: the size is remembered for the session, but a turn left over from a shape drawn minutes ago would surprise; within one locked session it is a way to draw a row of turned shapes.*
