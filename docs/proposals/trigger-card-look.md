# A new look for the trigger card

## TL;DR

The owner finds the trigger card "ugly and convoluted" (2026-11-24) and asked for a mockup of other ways to draw it. **Nothing is picked yet.** The mockup is [design/mockups/triggers.html](../design/mockups/triggers.html): 12 options, one card at a time, with two example triggers. The owner's favourites so far are **Branch** (11) and **Scratch** (12), and before them **Tree** and **Flow**. Next: the owner picks one, then it is written into [design/controls.md](../design/controls.md) and built as a v4 fix.

## The options in the mockup

| # | Name | In one line |
|---|---|---|
| 1 | Now | Today's card, for comparison |
| 2 | Chips | A lane for When, If and Do; each changeable word is a chip coloured by its kind |
| 3 | Icon rows | Each part is an icon tile, a verb and its details; click a row to edit it in fields |
| 4 | Blocks | Soft coloured blocks, the event on top |
| 5 | Flow | A vertical line through the event, the check and the actions; a Wait is a dashed "2 s later" gap |
| 6 | Steps | Plain lines with a quiet When, If, Do label |
| 7 | Folded | One line per trigger, opened by a click |
| 8 | Sentence | The whole trigger as one sentence, changeable parts as grey pills |
| 9 | When / Then | One box for the event, one for the actions |
| 10 | Tree | The event is the root, everything else hangs under it like a file tree |
| 11 | Branch | Tree and Flow merged: one line per part with its own outline icon, thin tree lines, actions after a Wait hang under it |
| 12 | Scratch | Snap-together blocks in Scratch's colours: an event block on top, a C-shaped If wrapping the actions it guards, a box per changeable part, corners and teeth slightly rounded |

## What the owner said, so the next round doesn't repeat it

- **Too much at once is the worst fault.** The first mockup showed 11 variants with pros and cons side by side, and the owner "almost died". Show one card at a time, few words around it.
- **Spacing matters most.** Nothing may touch its container's edge: the mockup uses 12 px inside a trigger, 8 px between rows, 8 px around the card.
- **No underlines, no filled circle markers, no lines that wrap.** Branch's first look had all three and was "very ugly and convoluted". Keep each part on one line; shorten the words, or cut with "…", rather than wrap.
- **Each changeable part must look separate.** "other has tag player" in one colour read as one thing, though `other`, `has tag` and `player` are three choices. Branch tells them apart by colour alone (entity blue, value violet, amount green, choice white, fixed words grey); Scratch and Blocky give each its own box.
- **The event names who touches:** "When **other** starts touching this", not "something starts touching this" or "Other starts touching this". The sentence starts with When where no label says When, and `other` is blue like an entity, with no chip or menu, since it can't be changed.
- **Only a little roundness.** The owner didn't like the first, rounded Scratch look; a square version (Blocky) followed. Then Blocky got 4 px corners and teeth rounded by 3 px, became the only Scratch option, and took its name (owner, 2026-11-24). Its teeth are square tabs, and no notch is cut: the tooth above always covers where it would be. The 2 px gap is a ring around the body and the tooth (box-shadow), so the hole is the tooth plus 2 px on every side, corners rounded by 5 px; drop-shadows drew it with near-square corners, so the hole didn't match the tooth (owner).
- **No cooldown; a trigger rests by switching itself off** (owner, 2026-11-24). Its actions start with "Set this Enabled to false" and end with "Wait 3 s" and "Set this Enabled to true", plain Set blocks like any other (owner, 2026-11-24: not a special "switch this trigger off" block). *Enabled* is a new word for the trigger's on/off value: not in the glossary yet, see Open. The time counts from the end of the actions, not from the firing, and a firing whose check fails switches nothing off, since the blocks sit inside the If. Repeat keeps every time (drawn as nothing) and once per run (not drawn yet). *Needs a requirement change*, see Open. *Rejected* for the cooldown: a footer line; a block under the event worded "cooldown 3 s" (jargon), "rest 3 seconds" ("horrible") or "do and rest for 3 seconds"; "ignore touches for 3 seconds"; a ⏱ badge on the event block; the event block's first word as a menu ("when", "the first time", "at most every 3 seconds"), which hides its choices; a block at the end of the actions, which reads as if the time starts after them, though a cooldown starts at the firing; a C-shaped "every 3 seconds" block, which read like a timer; "at most once every 3 s", too hard to read; "not again for 3 s" inside the event block. A Wait at the end alone can't do it, since a firing during a Wait starts its own run.
- **Block colours: don't invent a palette.** Three invented ones were each worse (owner, 2026-11-24): the first clashed, with white text on mid colours; a muted one at one OKLCH lightness turned brown and dull; light pastel blocks with near-black text were "absolutely horrible". Now the blocks use the editor's own way: a dark surface tinted with the kind's colour, the editor's `--text` on it, the icon in the full colour, changeable parts as the editor's fields, and a 2 px gap tracing each block's outline.
- **Scratch's categories in deeper colours** (owner, 2026-11-24: "#3d66c3, #2f897e, #b88133, etc.", replacing Scratch's own bright colours, which replaced the tinted dark blocks below): **a colour per kind of block, whatever it changes** (owner, 2026-11-24: every Set is blue, Position or Enabled): amber `#b88133` for the event, teal `#2f897e` for the If, blue `#3d66c3` for Set, violet `#7d58b8` for Add, rose `#ad4a7c` for Wait, red `#b5473d` for Destroy (Claude, in the owner's tone); white words and icons, menus in the block's colour darkened by a quarter, numbers as white ovals with Scratch's grey text.
- **Every block starts with one icon** saying what it does (the event's, If's split, each action's, Wait's hourglass, the power icon of switching a trigger off or on), in the block's full colour; the If's closing bar has none (Claude, asked to decide, 2026-11-24).
- **Only If holds other blocks.** A trigger is When, If, Do, with no nesting beyond that: one If, its checks joined by "and", wrapping the whole Do list since its checks guard every action. When is the top block, Wait and the actions plain blocks; a C-shape for Wait would suggest a scope that doesn't exist (Claude, asked to decide, 2026-11-24).
- **A time's unit is a menu**, "seconds", not a fixed "s", so ticks can be offered later (owner asked for "frames"; the glossary's word is tick) (owner, 2026-11-24).
- **A component value shows its path** (owner, 2026-11-24): "set this Enabled to false" read as switching the whole entity off. Set's value box now shows the path from the entity, the steps dim and the value bright: `Transform › Position`, `Triggers › Timed door › Enabled`. *Rejected:* "this trigger" as a target with a bare `Enabled`, which hides where Position lives. The trigger's line is now 128 px wider than the 344 px Entity inspector, so it scrolls sideways.
- **Blocks are cut apart by the trigger's own background** (owner, 2026-11-24): the 2 px border around every block is the colour of the trigger it sits in, not a stronger shade of the block's colour.
- **Adding a block anywhere** (owner, 2026-11-24; look only in the mockup): hovering a Scratch block opens an empty "add a block" slot next to it, shaped like a block, the tooth above in its hole; a block with nothing under it shows its tooth while the slot is open. **A block has three bands: its top third opens the slot above it, its bottom third the slot below it, and its middle third, where its values are, opens none** (owner, 2026-11-24, replacing top and bottom halves): any open slot closes there (owner). The tooth is left out of the measure (owner). The If is two bars, each with its own three bands (owner, 2026-11-24, replacing the If measured whole): the top bar's top third opens the slot above the If, its bottom third the first slot inside it; the bottom bar's top third opens the last slot inside it, its bottom third the slot after the whole If; both middles, and the arm, open none. The event has nothing above it, so its top third is like its middle (Claude). The cursor shows the hovered band: an up arrow over a band that opens the slot above, a down arrow over one that opens the slot below, the plain arrow over a middle (owner asked for a cursor per band, 2026-11-24; which cursors, Claude, standing yes). Slots open only on hover, and the card has no other Add button (owner: one kind of add button, not two). **The hovered block never moves:** the script keeps the height it has with no slot open, and when a slot opens or closes above the hovered block, the script (the box that also scrolls sideways) scrolls by the slot's height at once, so the block, and the point of it under the mouse, stay where they were; otherwise a value box couldn't be clicked (owner, 2026-11-24). When the open slot would be clipped by the script's view, above or below, wherever the hovered block is, the script scrolls smoothly by what's needed to show all of it, the hovered block moving with it (owner, 2026-11-24). Where the script can't scroll that far, an empty strip above or below its blocks makes the room, and the script glides back to its start over 400 ms when the mouse has left it, not at once (owner: it jumped) (Claude). **Nothing moves for 200 ms** after the mouse asks for a change (owner, 2026-11-24). **Then a slot takes 400 ms** (owner): first the blocks move apart to make its room (200 ms), then the slot fades in (200 ms; at 100 ms it looked instant, owner); closing runs the other way. Every move eases in and out (owner: not linear). So a mouse moving fast reaches the block it's heading for before anything moves; the script scrolls on every frame of it. *Open:* a block before or after the If isn't guarded by its check, which breaks "the If wraps the whole Do list" above.
- **The script's scrollbars are thin rounded bars drawn over the blocks** (owner asked for better-looking scrollbars, 2026-11-24): they take no room, so the vertical one appearing no longer narrows the script and calls up the horizontal one (owner); they show while the mouse is on the script and widen under it, and their thumbs can be dragged (Claude). **Where the script hides blocks past an edge, that edge fades them into the card** instead of cutting them, on any side, only where something is hidden (owner, 2026-11-24); the fade is 18 px, shorter while less than that is hidden (Claude).
- **No highlight stripe on the event block.** The square Scratch's lighter band on top was "ugly"; the event block is one flat colour.

## Open

- **Which option**, and whether parts of two are combined.
- **The requirement change for resting** (owner's yes, 2026-11-24, not written into the requirements yet): Repeat drops its cooldown choice, and **a trigger that switches itself off doesn't cancel the run doing it**, so that run can wait and switch it back on. Today switching a trigger off cancels all its waiting runs ([requirements/triggers/triggers.md](../requirements/triggers/triggers.md), Wait), and so does the game (`architecture/triggers-in-play.md`, Waiting runs). Also to settle: whether old levels' cooldowns become these blocks when loaded.
- **The word *Enabled*:** the trigger's on/off value, as Set's Value menu shows it. It has no name in the glossary or the requirements yet (Change value sets "a trigger's on or off"). Add it to the glossary before it goes past the mockup.
- **How once per run is drawn**, Repeat's other choice; the mockup has no example of it yet.
- **The game's own wording:** the real card and [requirements/triggers/triggers.md](../requirements/triggers/triggers.md) still say "When something starts touching this". Changing it to "other" means changing the requirement, the When menu and the tests. Asked, not answered yet (2026-11-24).
- **A wider Entity inspector:** the mockup draws it 344 px wide, not 300 px (owner, 2026-11-24: 340, plus 4 for the blocks' 2 px border), so Scratch's longest lines ("set this Position to 0, -200", "when other starts touching this") fit with no sideways scroll; at 300 px they needed 42 px more. Each block is as wide as its words, and the script still scrolls sideways if a line is longer. Taking it means changing the Entity inspector's starting size, a requirement ([requirements/editor/workspace.md](../requirements/editor/workspace.md), `--entity-inspector` in [design/tokens.md](../design/tokens.md)).
